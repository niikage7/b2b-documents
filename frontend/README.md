# Фронтенд

SPA на React 19 + TypeScript, сборка Vite. Шесть экранов из [описания интерфейса](../docs/interface.md): вход, загрузка и обработка пакета, все пакеты, разбор пакета, редактор документа, правила. Данные — по контракту API из «Требований к бэкенду» (6 октября); пока API нет, фронтенд работает на встроенном моке с тем же контрактом.

## Запуск

```bash
cd frontend
npm install
npm run dev:mock    # http://localhost:5173, мок API в браузере, бэкенд не нужен
npm run dev         # то же, но /api проксируется на API_PROXY_TARGET (по умолчанию http://localhost:8000)
```

В режиме мока вход — `methodologist`, `lawyer` или `specialist` с паролем `demo`. Данные мока лежат в `localStorage` браузера: ревью находок переживает перезагрузку. Кнопка «Сбросить демо-данные» на экране входа возвращает исходный набор.

```bash
npm run typecheck   # tsc
npm run lint        # eslint
npm test            # vitest: подсветка, выделение → смещения, раскладка выносок, проверка правила
npm run build       # статика в dist/ для настоящего API
npm run build:mock  # статика с моком — демо без бэкенда
```

## Docker

Образ собирает статику и раздаёт её через nginx. Запросы `/api/*` nginx проксирует на `API_UPSTREAM` (по умолчанию `http://api:8000`); для `/api/batches/{id}/events` буферизация выключена, а таймаут — 1 час, как требует SSE. `/healthz` — для healthcheck в docker-compose.

```bash
docker build -t b2b-frontend frontend
docker run -p 8080:80 -e API_UPSTREAM=http://host.docker.internal:8000 b2b-frontend
docker build -t b2b-frontend-demo --build-arg VITE_MOCK_API=true frontend   # демо на моке
```

## Как устроено

| Каталог | Что внутри |
| --- | --- |
| `src/api/` | `types.ts` — типы ответов API; `endpoints.ts` — по функции на эндпоинт; `http.ts` — запросы, ошибки `{error: {code, message}}`, загрузка с прогрессом; `events.ts` — SSE; `queries.ts` — кэш TanStack Query и применение событий SSE |
| `src/mocks/` | Мок API: те же пути, коды ответов и события SSE. Симулирует конвейер (извлечение, OCR по страницам, анализ по правилам), проверку файлов и zip без распаковки, тест правила |
| `src/pages/` | Экраны. Редактор документа — `pages/document/`, правила — `pages/rules/` |
| `src/components/` | Общие компоненты: кнопки, бейджи уровня, тосты, диалоги, меню, состояния загрузки и ошибок |
| `src/lib/` | Логика без React: отрезки подсветки, выделение мышью → `block_id + start + end`, раскладка выносок, проверка правила как в `ml/analysis/templates.py` |

Когда API опубликует `/api/openapi.json`, `src/api/types.ts` заменяется сгенерированными типами (`npx openapi-typescript`); имена полей уже совпадают. Мок после этого остаётся для демо и разработки без бэкенда.

### Правила продукта во фронтенде

- Цвета и счётчики приходят с бэкенда (`worst_level`, `findings`, `counters`, `review`); после правки находки фронтенд берёт новые значения из ответа `PATCH`, а не считает сам.
- Цвет не работает в одиночку: рядом всегда подпись «Критично», «Внимание», «Без рисков» или «Не проверен».
- Подсвечивается ровно `block.text[start:end]`. Ручная пометка — выделение внутри одного блока; смещения считаются по тексту блока, номер пункта в них не входит.
- Ручные пометки выглядят как находки ИИ и отличаются подписью автора.
- Конфликт версий (409 `version_conflict`) показывает актуальное состояние из `error.details.current`.
